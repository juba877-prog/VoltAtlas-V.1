# Audit Finding EE-08: Harmonics Modeling, Neutral Sizing Assumptions, and Unconsumed Inputs

## 1. Hypothesis
VoltAtlas implements a coarse Boolean harmonic model (`circuit.isHarmonic: Boolean`) that hardcodes the narrow 15–33% third-harmonic band of IEC 60364-5-52 Annex E. When checked, it applies a flat 0.86 phase-conductor derating and sets the neutral conductor size equal to the phase conductor size. It cannot accept quantitative harmonic data (total harmonic distortion THD% or 3rd-harmonic percentage $h_3$), cannot handle high-harmonic environments ($h_3 > 33\%$, such as IT server rooms, LED drivers, and variable frequency drives) where neutral current exceeds line current and neutral conductors must be sized larger than phase conductors (up to 1.61×–2.0×), completely ignores `isHarmonic` for single-phase circuits, and omits harmonic sizing when generating busbars in `ElectricalNetworkGraphBuilder.kt`. Furthermore, in `PfCorrectionEngine`, the database fields `harmonicFilter` and `detuningReactor` on `PfTransformerEntity` have no UI edit surface, acting as dead inputs that leave capacitor bank calculations locked in a permanent "REVIEW — HARMONIC/DETUNING INPUTS" state.

## 2. Evidence

   // For 15–33 % third-harmonic content the rating factor is 0.86 (the neutral counts

   val harmonicPhaseFactor = if (circuit.isHarmonic && circuit.phases.trim().startsWith("3")) 0.86 else 1.0

## 3. Reproduction / Hand Calculation

### Scenario: Heavy Non-Linear Load (Data Center / LED Lighting Installation)
- **Parameters:** 3-phase, 400 V, $I_b = 100\text{ A}$, triplen harmonic content $h_3 = 40\%$ of fundamental line current.
- **Physics of Triplen Harmonics in 3-Phase Systems:**
  Because third harmonics are zero-sequence, they add arithmetically in the neutral conductor:
  $$I_N = 3 \times I_b \times h_3 = 3 \times 100\text{ A} \times 0.40 = \mathbf{120\text{ A}}$$
  The neutral conductor carries 120 A continuously, which is **1.20× the line current**.

#### Standard Engineering Design (IEC 60364-5-52 Annex E Table E.52.1):
- For $33\% < h_3 \le 45\%$, line conductor selection is based on the **neutral current**.
- A rating factor of $0.86$ is applied to the neutral current:
  $$I_{\text{required, neutral}} = \frac{I_N}{0.86} = \frac{120\text{ A}}{0.86} = \mathbf{139.5\text{ A}}$$
- Conductor chosen based on 139.5 A (Cu/XLPE in ducts): **$50\text{ mm}^2$** ($I_z = 153\text{ A}$).
- Both line and neutral must be sized for at least 139.5 A ($50\text{ mm}^2$).

#### VoltAtlas Calculation As-Coded:
- Circuit has `isHarmonic = true`.
- Line current $I_b = 100\text{ A}$ derated by $0.86$:
  $$I_{\text{required}} = \frac{100\text{ A}}{0.86} = \mathbf{116.3\text{ A}}$$
- VoltAtlas selects **$35\text{ mm}^2$** ($I_z = 125\text{ A}$).
- Neutral is assigned equal to phase size: **$35\text{ mm}^2$**.
- Operating current in neutral: $120\text{ A}$.
- Effective derated capacity of $35\text{ mm}^2$ with 4 loaded conductors: $125 \times 0.86 = 107.5\text{ A}$.
- Thermal overload on neutral conductor:
  $$\text{Overload} = \frac{120\text{ A} - 107.5\text{ A}}{107.5\text{ A}} = \mathbf{+11.6\%\text{ continuous thermal overload}}$$
- If $h_3 = 50\%$, $I_N = 150\text{ A}$, overload on $35\text{ mm}^2$ neutral is **$+39.5\%$**, presenting a severe fire and failure hazard.

## 4. Impact
- **Non-conservative Neutral Sizing:** In modern commercial buildings and data centers where non-linear loads routinely exceed 33% THD, VoltAtlas undersizes both phase and neutral conductors.
- **Dead Inputs in PFC:** Users cannot resolve the "REVIEW — HARMONIC/DETUNING INPUTS" banner in Power Factor Correction because no UI exists to provide the required transformer filter configuration.
- **Scope Claims:** No explicit claim of "harmonic-complete" is made in the code; however, the UI label "Harmonic Load" without a percentage qualifier misleads practicing engineers into assuming the tool performs comprehensive harmonic analysis.

## 5. Classification
**CONFIRMED** (Incomplete harmonic domain model, undersized neutral risk for $h_3 > 33\%$, unconsumed PFC inputs).

## 6. Proposed Severity
**R1 — Engineering Blocker** (Risk of thermal damage to neutral conductors in high-harmonic circuits; broken PFC UI workflow).

## 7. Recommended Option for Owner Decision
- **Option (a) [RECOMMENDED]: Multi-Band Harmonic Input & Wire Unconsumed Fields**
  1. Replace the Boolean `isHarmonic` with a tri-state or banded enum in `CircuitEntity`:
     - `NONE` ($< 15\%$ third harmonic): standard phase sizing, reduced neutral permitted.
     - `MODERATE` ($15\% - 33\%$): current behavior (phase derated $\times 0.86$, 100% neutral).
     - `HIGH` ($> 33\%$): neutral-current sizing basis per IEC 60364-5-52 Annex E ($I_N = 3 \cdot I_b \cdot h_3$, rated factor applied to $I_N$, neutral conductor sized larger than line).
  2. In `ElectricalNetworkGraphBuilder.kt:1449`, pass `hasHighHarmonics = circ.isHarmonic` into `BusbarSizingEngine.sizeBusbar`.
  3. In `PowerSystemsScreen.kt`, add configuration chips for `Harmonic Filter: Yes/No` and `Detuning Reactor: Yes/No` to enable completion of PFC calculations.

- **Option (b): Restrict & Explicitly Document Boolean Scope**
  1. Retain Boolean `isHarmonic`, but change UI label from `Harmonics` to `Harmonics (15–33% 3rd Harmonic Band only)`.
  2. Add an explicit error / block condition if user attempts to size data center / high-THD circuits.
  3. Provide default `"Yes"` fallback or remove the dead PFC check in `PfCorrectionEngine`.

## 10. Owner Decision: D-EE-08 = APPROVE OPTION B — CONTROLLED HARMONIC SCOPE + TRANSPARENT DISCLOSURE + SAFE BUSBAR FALLBACK + PFC INPUT WORKFLOW FIX

### Owner Decision Summary:
The owner formally reviewed the EE-08 findings and approved **Option B** with strict scope controls:
1. **Cable Harmonic Modeling Scope & Disclosure:**
   - Retain existing Boolean `isHarmonic` flag on `CircuitEntity`.
   - Do NOT add $h_3\%$ or THD% numerical fields to the data model or execute Room schema migrations in this ticket.
   - Boolean `isHarmonic = true` models strictly the 15–33% third-harmonic band per IEC 60364-5-52 Annex E Table E.52.1 (0.86 phase derating factor and full-size neutral conductor).
   - In UI (`LoadStepContent.kt` and `ReviewStepContent.kt`), clarify the label to `"Harmonics (15–33% 3rd Harmonic Band)"` with supporting description.
   - In PDF report (`Sections.kt`), add transparent disclosure that automated sizing is strictly limited to the 15–33% 3rd-harmonic band and harmonic content >33% requires manual neutral-current sizing and engineering review.

2. **Safe Busbar Fallback for Harmonic Switchboards:**
   - When a switchboard or its circuits have `isHarmonic = true`, busbar sizing cannot assume standard 50% reduced neutral or force unverified 200% high-harmonics sizing without Tier-F engine modification.
   - In `ElectricalNetworkGraphBuilder.kt`, for harmonic switchboards, set `busbarNeutralStr` to `"NOT EVALUATED (MANUAL REVIEW)"` while preserving all valid phase and earthing sizing.

3. **Power Factor Correction (PFC) Workflow Fix:**
   - In `PowerSystemsScreen.kt` (`PfCorrectionPanel`), add interactive configuration controls (selectable chips for `"Yes"`, `"No"`, `"Not Provided"`) for `harmonicFilter` and `detuningReactor` on `PfTransformerEntity`.
   - Wire directly to `onSaveTx(...)` to persist settings into Room database.
   - When configured, `PfCorrectionEngine` evaluates `COMPLIANT` normally without modifying the frozen Tier-F engine.

4. **Tier-F Code Freeze:**
   - Zero modifications to `CableSizingEngine.kt`, `BusbarSizingEngine.kt`, or `PfCorrectionEngine.kt`.
   - Manifest verified 27/27 intact with 0 drift.
